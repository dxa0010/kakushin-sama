対象: `assets/fonts/`, `tools/charset.mjs`, `tools/make-fonts.mjs`,
`index.html`（`@font-face` と CSS フォントスタック）, `src/game.js`（canvas のフォント指定）
関連: `docs/test-specs/anoms-i18n.md`（L-14 / L-15 / L-21）, `docs/STEAM-RELEASE.md` P2-7
作成: 2026-08-28

## 1. なぜ要るのか（根拠）

### 1.1 要求由来: Proton / Steam Deck で日本語・中国語が出ない

**測定した事実（2026-08-28）。** ブラウザで `document.fonts` を列挙すると **空**だった。

```
document.fonts: {"loaded":[],"ready":true}
```

つまり本作は現状 `@font-face` を1つも持たず、日本語・中国語・キリル文字の
すべてを **OS 標準フォントに依存**している。Windows 実機では
`Yu Mincho` / `Meiryo` / `Noto Sans JP` が入っているので動く。

Steam Deck（Linux）で Windows ビルドを Proton 越しに動かす場合、Wine の
フォント環境には日本語・中国語フォントが**無いのが既定**である。この状態では
書類・図鑑・UI のほぼ全文が豆腐（□）になる。**遊べない。**

これは配信対象プラットフォームの要求（Steam Deck / Proton 対応）から直接来る。
「あったほうがよい」ではなく、**無ければ出荷できない**項目。

### 1.2 要求由来: zh-Hans には簡体字フォントが要る

`Noto Sans JP` の収録は JIS 系であり、簡体字専用の字（`银` U+94F6、
`汇` U+6C47、`缴` U+7F34 など）を持たない。zh-Hans の書類本文はこれらを多用する
（`白鹭银行` / `上年度汇算清缴记录`）。日本語フォントだけを同梱すると
**zh-Hans が豆腐になる**。よって ja 用と zh-Hans 用は別のフォントが要る。

**F-04 でこれを実測する**（推測で決めない）。zh-Hans を JP フォント運用に戻す変異を
入れると、F-04 が不足する簡体字を 100 字超列挙して失敗する（§5.4）。

### 1.3 要求由来: 異変が出す字はサブセットから落ちやすい（L-14 / L-15 の再掲）

`confusableOutputs()` が返す字（`ъ` `戸` `醫` `圧` `蕃` `斯` `顎` など）は
**素の本文に一度も現れない**。本文だけを走査してサブセットを作ると必ず落ちる。

落ちると豆腐になる。そして豆腐は「本物の異変ではない、目に見える差異」なので、
プレイヤーは豆腐を異変だと思って通報し、却下される。これは L-2（見えているものと
却下理由が一致すること）への正面からの違反であり、**難易度の問題ではなく不具合**。

### 1.4 設計時の仮定ではないこと（誤りの訂正）

作業中、以下2点を「不具合」と判断しかけたが、**実測の結果いずれも誤り**だった。
仕様の根拠として使わない。記録として残す。

| 疑ったこと | 実測結果 |
|---|---|
| zh-Hans の `白鹭银行` が繁体字 `鷺` で描画され、`简→繁` 異変を偽造している | **誤り。** 72px で描き比べたところ U+9E6D は簡体（`鸟`）で正しく描画されていた。21px の縮小画像で見誤った |
| en の `Form 1040（2024）` が全角括弧になっている | **誤り。** `(` の実測幅は 13.8px（全角なら 32px）。ASCII の括弧が明朝体で描かれていただけ |

## 2. 保証すること / しないこと

### 保証する

- 同梱フォントだけで、全5ロケールの**表示しうる全文字**が描画できる（豆腐が出ない）
- サブセットの入力文字集合は、**コードから機械的に導出**される（手書きの一覧を持たない）
- サブセット生成は**出荷物に含まれない**（生成済みの `.woff2` をコミットする）
  ── リポジトリの方針「ビルドはしない・依存は足さない」を破らない

### 保証しない（本仕様の範囲外）

- **UI 文言の翻訳**。現状 HUD・ポーズ・図鑑は全ロケールで日本語のまま。
  よって全ロケールが日本語フォントを必要とする。これは既知の未達であり、
  P2-7 では**フォントが無い問題だけ**を解く（翻訳は別項目）
- 字形の地域差（同一コードポイントの日中字形差）の追い込み。豆腐の解消が先
- Electron 実機での描画確認（P0-1 未着手のため実施できない）

## 3. 設計

### 3.1 ファミリと役割

コード内の既存スタックは3種類。それぞれに同梱フォントを先頭へ足す。

| 役割 | 現行の指定 | 用途 | 同梱元 |
|---|---|---|---|
| serif | `'Hiragino Mincho ProN','Yu Mincho',serif` | タイトル、書類の題字・氏名、`印`/`呪` | Noto Serif JP / SC |
| sans | `sans-serif` | HUD、項目名、ポーズ、図鑑 | Noto Sans JP / SC |
| mono | `ui-monospace,monospace` | 金額、日付、暗証番号 | Noto Sans Mono |

同梱フォントは**先頭に置くが、OS フォントを消さない**。実機に良い日本語フォントが
あるなら使わせない理由が無く、同梱は「無い環境の保険」である。

### 3.2 zh-Hans の切り替え

zh-Hans だけ SC 系フォントを使う。`@font-face` は5ロケール分すべて宣言してよい
（ブラウザは実際に必要になった face しかダウンロードしない）が、
**canvas は例外**である。canvas の `c.font` はフォントの読み込みを起動しないため、
最初の `drawDoc()` より前に `document.fonts.load()` を明示的に待つ必要がある。
待たずに描くと初回だけ OS フォントで描かれる（F-05）。

### 3.3 ライセンス

Noto は **SIL Open Font License 1.1**。再配布の条件は
(a) 著作権表示とライセンス全文の同梱、(b) Reserved Font Name を改変版に使わない。

サブセットは改変にあたるため、**ファミリ名を `Noto…` のままにしない**。
`Kakushin Sans` 等に改名する。これは体裁ではなく OFL の要求。

`THIRD-PARTY-NOTICES.md` とゲーム内クレジット（P7-1）の**両方**に追記する。
片方だけ直さないこと（クレジット画面のコメントに同じ注意書きがある）。

### 5.3 設計上の判断（実測に基づく）

**穴埋め face を2つに分けた。** 当初は「主フォントに無い字を1つの小さな face に
まとめる」設計だったが、生成ツールが自分で**賄えないことを検出して停止した**。

- `简`（U+7B80）── 日本語フォントに無い。言語選択の「简体中文」に要る
- `₽`（U+20BD）── **CJK 系フォント4つすべてに無い**。Noto Sans Mono だけが持つ

1つの元フォントで両方を持つものが無いため、提供元ごとに face を分けた。
ここで「黙って落とす」実装にしていたら、ロシア語の金額が全部豆腐になっていた。
**穴を検出したら例外で止める**方針は残すこと。

**等幅フォントは CJK を持たない。** Noto Sans Mono は `年月日` を持たないため、
`--f-mono` は sans へ落ちる並びにしてある（`2025年6月30日` のような日付のため）。

**`html[lang]` で zh-Hans のスタックを入れ替える。** 同じコードポイントでも
日中で字形が違うため、SC 系を先に出す。`src/game.js` は `document.documentElement.lang`
を設定する。

**canvas はフォントを自動で読まない。** `c.font` に未読込の face 名を書いても
黙って次のフォントへ落ちる。`loadFonts()` を `await` してから最初の書類を描く
（開始ボタンで待つ）。待たないと1枚目だけ OS フォントになり、2枚目から直るので
原因が分かりにくい。

**`loadFonts()` を `SC()` に依存させない。** モジュール上端から呼ぶため、
後方で `const SC` を宣言していると TDZ で落ちる。和字・簡体字・数字・₽ を
全部含む1つの probe 文字列を渡す形にした。

### 5.4 変異テスト（各ガードが実際に効くことの確認）

| 変異 | 捕まえたケース |
|---|---|
| `charsetFor` から `confusableOutputs()` を外す | F-02（異変の出力字が落ちている）、F-05 |
| 穴埋め face（`-1` / `-2`）を削除 | F-04（`₽` `简` が無い） |
| zh-Hans を JP フォント運用に戻す | F-04。簡体字 100 字超の不足を列挙して失敗 |

3件目の失敗メッセージは §1.2 の主張そのものの実測にもなっている
（`银 汇 缴 鹭 额 户 备 编 费 …` が日本語フォントに無い）。

### 5.5 実機（ブラウザ）での確認

着手前は `document.fonts` が **空**だった。実装後は **7 face すべてが `loaded`**。
画素比較で、`Kakushin Serif` / `Kakushin Sans SC` / `Kakushin Mono` / `Kakushin Gap`
のいずれも「代替フォントとは異なる画素で描かれている」ことを確認した。

> **幅では判定できない。** CJK の字はどのフォントでも 1em 幅なので、
> `measureText` は同梱 face と代替フォントで一致する。最初この方法で測って
> 「効いていない」と誤判定した。判定は画素で行うこと。

書類の描画は ja / zh-Hans / ru / es を目視確認済み。

### 5.6 副次的な変更

`M` キーのミュート通知から絵文字（🔇🔈）を外した。同梱フォントはどれも絵文字を
持たず、Proton には絵文字フォント自体が無いので豆腐になる。2字のために絵文字
フォントを同梱する価値は無い。

### 5.7 積み残し

- **UI 文言が全ロケールで日本語のまま**（§2 の範囲外）。このため en / ru / es でも
  日本語フォントを同梱する必要があり、サブセットの 7 割が日本語 UI 由来である。
  UI を翻訳すれば、これらのロケールのフォントは大幅に小さくできる
- Electron 実機（Proton / Steam Deck）での確認は P0-1 待ち。
  **本仕様が守るのは「同梱漏れが無いこと」までで、実機で読めることの確認ではない**
- 可変フォント軸（wght）を残したまま。単一ウェイトへ固定すればさらに縮むが、
  現状 0.69MB で上限に余裕があるため見送った
