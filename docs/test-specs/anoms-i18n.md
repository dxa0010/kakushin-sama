# 異変の多言語化 仕様書（anoms-i18n）

ケースIDは `L-n`。テストコードは `tests/unit/anoms.test.js`、実装は `src/anoms.js`（純粋モジュール）。

## 0. 対象ロケールと根拠

Steam Hardware & Software Survey 2026年7月の言語シェア上位4＋日本語。
出典: <https://store.steampowered.com/hwsurvey/Steam-Hardware-Software-Survey-Welcome-to-Steam>

| ロケール | シェア | 順位 |
|---|---|---|
| `en` English | 39.61% | 1 |
| `zh-Hans` 简体中文 | 22.52% | 2 |
| `ru` Русский | 9.30% | 3 |
| `es` Español（Spain） | 4.91% | 4 |
| `ja` 日本語 | 2.43% | 7（原語なので必須） |

- `Spanish – Spain` (4.91%) と `Spanish – Latin America` (0.89%) は別集計だが、中南米のプレイヤーも es-ES を選ぶ傾向があるため**単一の `es` で両方を賄う**
- `Portuguese-Brazil` 4.38% が僅差の5位。ブラジルは徴税を「o Leão（獅子）」と呼ぶ文化があり本作と相性が良い。**次の追加候補**として保留
- `Traditional Chinese` 1.33% は今回外す。字形が違うので L-5 の表を別に作る必要があり、コストが `zh-Hans` と同等になる

## 1. 大原則（これを外すと全ケースが崩れる）

### L-1: 舞台は日本のまま。制度を国別に差し替えない

参照点である8番出口・Chilla's Art は日本設定のまま英語字幕で海外に届いている。異国性は障壁ではなく売り。
**書類は日本の税務書類であり続け、その表示言語だけが変わる。** 通貨は全ロケールで `¥` を維持する。

### L-2: 異変は「現実の税制知識」ではなく「ゲーム内で提示された情報との矛盾」で気づけること

v21 で暗証番号に適用した原則（必須アイテムだけで解ける）の再適用。
日本人プレイヤーは現実の知識で近道できるが、**その近道が無い前提で成立していなければならない。**
根拠: 要求由来（海外配信の決定）。

### L-3: 文化固有の恐怖は「置き換える」のではなく「図鑑で教える」

異変図鑑（`save.codex`）は既に永続化されている。ここに1行の由来を添えれば、
異変そのものを差し替えずに文化的な重みを渡せる。**置き換えは最後の手段。**
根拠: 設計時の仮定。置き換えはコストが5倍になり、L-1 の武器（異国性）も削るため。

### L-4: 異変は「読めなくても」気づけることを優先する

氏名・年号は全書類に印字されるので、**字形の比較**で判定できる。読解を要求しない。

## 2. 16種の判定（`src/game.js:84` の `ANOMS` 全件）

### 2.1 そのまま全ロケールで成立する（10種）

`minus` 負の金額 / `stamp` 逆さの印 / `mirror` 鏡の書類 / `date` 存在しない日付 /
`soul` 魂の対価 / `kami` 名乗る書類 / `eye` 見ている印 / `blur` 濡れた文字 /
`mark` 透かしの顔 / `ju` 朱の呪

補足すべき点だけ:

- **L-5: `minus` は括弧記法を使ってはならない。** 英語・スペイン語の会計慣習では負数を `(1,200,000)` と括る。
  括弧で出すと「会計的に正しい表記」に見えて異変にならない。**明示のマイナス記号（U+2212）を金額の先頭に置く。**
- **L-6: `stamp` / `eye` / `ju`（印章系）は `ja` `zh-Hans` `ru` で特に強く効く。**
  日中は印鑑・印章の文化、ロシアは公文書の печать（гербовая печать）文化が強い。
  `en` `es` では視覚的には成立するが文化的な重みが落ちる。**対応は不要**（L-3 により図鑑で補う）
- **L-7: `date` の日付書式はロケール規約に従う。** `ja` 令和8年2月30日 / `en` February 30 /
  `zh-Hans` 2月30日 / `ru` 30 февраля / `es` 30 de febrero。2月30日は**どの暦にも存在しない**ので判定は不変

### 2.2 設計の修正で全ロケール共通にできる（3種）

置き換えではなく、**気づきの根拠を変える**ことで対応する。

#### L-8: `era` 存在しない年号 — 全書類に年号年を印字して相互参照を成立させる

現状「昭和107年分」は**昭和が64年で終わったことを知らないと気づけない**（`ja` 以外で死ぬ）。
「令和∞年分」は∞が数値でないので全ロケールで残る。

**修正: 真正な書類はすべて同一の年号年（令和8年分）を印字する。**
現状 `DOCSPECS` に年号年のフィールドが無く、`mycard` の有効期限に「令和10年5月」があるだけ。
全書類に印字すれば、「昭和107年分」は**他の4枚が令和8年分だという矛盾**として検出でき、
歴史知識が不要になる。異変の内容は1文字も変えずに済む。

- 変異の種類: (a) 数でない年（令和∞年） (b) 他の書類と異なる元号（昭和107年・存在しない元号）
- **`ja` 以外では元号を原語のまま音写する**（Reiwa / 令和 / Рэйва / Reiwa）。翻訳しない＝L-1

#### L-9: `name` 一字ちがいの氏名 — 氏名は全ロケールで漢字のまま据え置く

`PLAYER_NAME = "三月 十五"` は氏名であると同時に**暗証番号のフォールバック手掛かり**
（`src/game.js:2662` が「氏名欄には、いつもの名前があった」と再提示している）。
**訳すとパズルの救済経路が壊れる。**

**修正: 全ロケールで氏名を「三月 十五」（漢字）のまま印字する。**
氏名は全書類に印字されるので、異変判定は**字形の比較**で成立する（十五 vs 十**六** は
読めなくても形が違う）。L-4 の適用。

- 暗証番号の手掛かり文だけ、意味を開示する。例: `en` "...the name on the return: *Sangatsu Jūgo*. March. Fifteen."
- 差し替える文字は**字形が明確に違うもの**に限る（十五→十六 は可、三→王 のような細差は不可）

#### L-10: `four` 四づくし — 4 のまま維持し、図鑑で由来を教える

`ja` `zh-Hans` では 4＝死 が完全に通じる（`ko` も同様）。`en` `ru` `es` では
「数値が全部4だ」と**検出はできるが恐怖にならない**。

**修正: 全ロケールで 4 を維持する。** 理由3つ:
1. 書類は日本の税務書類なので、日本の忌み数であることが**フィクション内で正しい**
2. `en` で 666 に差し替えると、日本の税務書類のトーンから外れる
3. 恐怖は図鑑の名前と1行の由来で渡せる（L-3）。例: `en` codex "The Number of Death — in Japan, *four* is read *shi*, the same sound as *death*."

### 2.3 ロケールごとに中身を作り直す（2種）

ここが実作業の本体。**翻訳では作れない。**

#### L-11: `typo` 入れ替わった題字 — 文字体系ごとに機構が違う

現状は題字の先頭2文字を入れ替える（`[t[0], t[1]]`）。

| 文字体系 | 機構 | 例 |
|---|---|---|
| CJK（`ja` `zh-Hans`） | **先頭2文字を入れ替える**（1文字＝1形態素なので入れ替えが強い違和感になる） | 支払調書 → 払支調書 / 支付记录 → 付支记录 |
| アルファベット系（`en` `ru` `es`） | **単語内の隣接2文字を入れ替える**（先頭2文字の入れ替えは "aPyment" となり、異変ではなくバグに見える） | Payment → Paym**ne**t / Справка → Спр**ва**ка / Registro → Reg**si**tro |

**根拠**: `typo` は `sub: true`（巧妙系）に分類されている。先頭を崩すと巧妙ではなくなり、
分類と挙動が矛盾する。単語内転置は「見落としやすい誤字」の典型で、分類と一致する。

#### L-12: `label` 化けた項目名 — 5ロケール分の混同表を作る

現状 `LOOKA = { 金:"全", 医:"圧", 番:"蕃", 期:"斯", 額:"顎", 号:"呂" }` は**漢字の字形**の話。
各言語に固有の「見た目が近くて意味が違う文字」の実例があり、**どれも現実の詐称手法として通用する**。

| ロケール | 方式 | 表 | 例 |
|---|---|---|---|
| `ja` | 漢字の字形 | 金→全, 医→圧, 番→蕃, 期→斯, 額→顎, 号→呂（既存を維持） | 支払**全**額 |
| `zh-Hans` | **簡体字→繁体字/異体字への化け** | 户→戸, 医→醫, 号→號, 额→額, 类→類, 备→備, 编→編, 费→費 | 用**戸**识别号 |
| `ru` | **キリル文字内の紛らわしい対＋旧正書法** | ь→ъ, е→ё, и→й, щ→ш, ц→ч, з→э | Парол**ъ** |
| `en` | **ラテン文字のホモグリフ** | m→rn, W→VV, l→I, d→cl, O→0 | A**rn**ount / **VV**ithholding / Tota**I** |
| `es` | **ダイアクリティカルの脱落** | í→i, ú→u, ó→o, é→e, á→a, ñ→n | Categor**i**a / Contrase**n**a |

設計上の要点:

- **置換は「1文字」ではなく「1箇所」。** `en` の最良の手（`m→rn` `W→VV` `d→cl`）は
  1文字が2文字に増えるので、長さ固定を要求するとラテン文字圏で最も効く方式が使えない。
  保証すべきは「置換箇所がちょうど1つで、その前後が不変」であること
- **`es` の「アクセント位置ずれ」（Número→Numeró）は採用しない。**
  脱落と付加の2箇所変更になり、上の「1箇所」規律に反する。脱落のみを使う
- **混同表のエントリは、必ずどこかの項目名に出現しなければならない**（L-12b）。
  出現しない字は永久に発火せず、「対応した」という錯覚だけが残る。
  この制約から `en` の項目名を1つ調整した: 受診回数の英訳を "Number of visits" ではなく
  **"Outpatient visits"** にする（`O→0` の当たり先を作るため）。`ru` の品名は
  «Наименование» ではなく **«Название»** にする（`з→э` の当たり先を作るため）
- **`zh-Hans` の「簡→繁への化け」が5つの中で最も強い。** 簡体字話者は繁体字/日本字形を
  「古い・よそのもの」として即座に感じ取るが、字形は近いので巧妙さも保たれる。
  「文字が旧字に化ける」は本作の題材（何十年も前から続く事務）と噛み合う
- **`ru` の `ь→ъ` は革命前正書法**（1918年廃止）。語末の ъ はロシア語話者に強い違和感を与え、
  かつ「書類が本来より古い」という恐怖のビートになる。単なる誤字より上等
- **`ru` でラテン文字を混ぜる方式（а→a, о→o, с→c）は採用しない。** 現実の
  フィッシング手法として最強だが、**フォントが同一字形で描くとプレイヤーには見えない**。
  見えない異変は L-2 の公平性に反する
- **`es` の `ñ→n` は「Contraseña（暗証番号）→ Contrasena」に当てると効く。**
  ⚠️ `Año → Ano` は語義が卑語になり、スペイン語話者は確実に気づくが、
  「ゲーム側は一切ボケない」という本作の規律に触れる。**既定では表から除外し、採用は別途判断とする**
- **`en` の `m→rn` / `W→VV` は本家（漢字）より強い可能性がある。** ラテン文字のホモグリフは
  ドメイン詐称の実手法として広く知られており、「偽物の書類」という文脈に直接乗る

## 3. 暗証番号パズルへの波及（要対応）

### L-13: 暗証番号 `0315` は MMDD 順であり、ロケールによって規約が違う

| ロケール | 日常の日付書式 | プレイヤーが最初に試す4桁 |
|---|---|---|
| `ja` | 2026/03/15 | **0315** ✓ |
| `zh-Hans` | 2026-03-15 | **0315** ✓ |
| `en`（米） | 03/15/2026 | **0315** ✓ |
| `en`（英） | 15/03/2026 | 1503 ✗ |
| `ru` | 15.03.2026 | 1503 ✗ |
| `es` | 15/03/2026 | 1503 ✗ |

**修正: 答えは `0315` に統一し、手掛かり文で順序を明示する。**
書類は日本の様式（年→月→日）なので、月が先であることは**フィクション内で正しい**。
`ru` `es` `en-GB` の手掛かり文には「月、そして日」に相当する語を明示的に入れる。

`src/pin.js` の `answer` は呼び出し側からの注入なので**モジュールの変更は不要**（A-7 の設計が効いている）。

## 4. フォントへの波及（要対応）

### L-14: 混同表の出力字は、素の本文には現れない字を含む

グリフのサブセットを作るとき、**本文の文字だけを拾うと異変が豆腐になる。**
サブセット生成は L-12 の表の**出力側**も入力に含めなければならない。

対象字: `全 圧 蕃 斯 顎 呂`（ja） / `戸 醫 號 額 類 備 編 費`（zh-Hans） /
`ъ ё й ш ч э`（ru） / `í ú ó é á ñ`（es） / `rn VV I cl 0`（en＝既存字で足りる）

### L-15: 必要な字形の集合は2つのCJKフォントを要求する

`ja` と `zh-Hans` は同じコードポイントでも字形が違う（例: 直・骨）。
**Noto Sans JP と Noto Sans SC の両方が必要。** Cyrillic とラテン拡張（ダイアクリティカル）も要る。
`zh-Hans` の表は繁体字形（醫 號 類 費）を出力するので、**SC フォントがそれらの
コードポイントを持っているかを実測で確認すること**（持っていない場合は表を差し替える）。

現状 assets は27MB。フォントを素で足すと配布サイズが跳ねるため、**サブセット化は必須**
（本文は約3,900文字しかないので、L-14 を守れば十分に小さくできる）。

## 6. 設計上の結論（要約）

当初「4種が英語で成立しない」と見積もったが、精査の結果**作り直しが必要なのは2種**（`typo` `label`）だけ。
`era` `name` `four` は**異変の中身ではなく気づきの根拠を直す**ことで全ロケール共通にできる。

さらに `label` については、**`zh-Hans`（簡→繁への化け）と `ru`（革命前正書法）と `en`（ラテンホモグリフ）は
原語版より強くなる可能性がある。** ローカライズが劣化ではなく強化になる珍しいケース。

## 7. 未決事項（実装で判明したもの）

### L-20: 混同表の当たり頻度が偏っている（要判断）

`label` は候補を等確率で選ぶため、**項目名によく出る字が圧倒的に多く当たる。**
実測（`confusables()` の全候補を列挙）で判明した偏り:

- `ru`: `е→ё`（12箇所）と `и→й`（13箇所）が支配的。最も効く **`ь→ъ`（革命前正書法）は2箇所しかなく、ほとんど出ない**
- `en`: `l→I`（8箇所）と `d→cl`（7箇所）が支配的。`O→0` は1箇所のみ
- `es`: `ó→o` が5箇所で最多。`ñ→n`（Contraseña）は1箇所
- `ja` `zh-Hans`: おおむね均等（漢字は各項目名に1〜2箇所しか無いため）

**判断が必要な点**: エントリごとに重みを持たせて、質の高い異変（`ь→ъ` / `O→0` / `ñ→n`）を
出やすくするか、等確率のままにするか。等確率のままでも異変としては成立するので**バグではない**が、
「一番効く手が20回に1回しか出ない」状態になっている。

### L-21: `zh-Hans` の繁体字グリフのフォント実測（未実施）

L-15 のとおり、`zh-Hans` の混同表は繁体字形（戸 醫 號 額 類 備 編 費）を出力する。
Noto Sans SC がこれらのコードポイントを持つかは**実測していない**。
持たない場合は表の差し替えが必要（簡体字内の紛らわしい対 己/已/巳・未/末・天/夭 等へ）。

### L-22: `src/game.js` への配線（未実施）

`src/anoms.js` は純粋モジュールとして完成し `npm test` に載っているが、
**`src/game.js` はまだ自前の `DOCSPECS` / `ANOMS` / `LOOKA` / `PLAYER_NAME` を持っている。**
配線には以下が必要:

1. `game.js` から `anoms.js` を import し、重複定義を削除する
2. **書類の描画に年号年の欄を追加する**（L-8 の相互参照が成立する前提）
3. `Math.random` を `applyAnom` に `rng` として渡す
4. `anomName()` を `anomMeta(id, locale).name` に置き換える
5. 暗証番号のフォールバック文を `pinHint(locale)` から取る
6. 言語切替UI（`docs/STEAM-RELEASE.md` の P2-4）と接続する

配線は挙動を変えるので、着手前に `tools/shot.mjs` でスクリーンショットのハーネスを通すこと。

## 8. 怪異の名前とタイトル（2026-08-19 決定）

### L-23: 名前をタイトルで提示する — 既存の公平性の欠落の修正

**これはローカライズの都合ではなく、日本語版に元から入っていた欠陥の修正である。**

多言語化の検討中に `カクシン` を全リポジトリ grep したところ、プレイヤーの目に触れる場所は
2箇所しか無く、しかもどちらも**異変そのものの中身**だった。

| 場所 | 内容 |
|---|---|
| `src/game.js` 異変 `issuer` | 発行元が `株式会社カクシン` になる（却下理由「発行元が実在しません」） |
| `src/game.js` 異変 `kami` | 氏名欄が `カクシン様` になる（却下理由「氏名が人間ではありません」） |

他は開発者向けコメント（`/* ---------- 怪人「カクシン様」 ---------- */` 等）と docs だけで、
**タイトル・ポスター（「納税シロ」「重加算税」）・顔のプレート（「重加算税」）のいずれにも名前が無い。**

つまり `issuer` は、プレイヤーが `株式会社カクシン` を偽物と判断する根拠を持たないまま
却下を要求していた。これは L-2（ゲーム内で提示された情報だけで気づけること）の違反であり、
v21 で暗証番号に適用した「必須アイテムだけで解ける」原則と同じ性質の欠陥である。
**ロケールに関係なく、日本語版にも存在していた。**

**対応:** 怪異の名前をタイトルに入れ、開始前に必ず読ませる。

- 日本語タイトル: `カクシン様 ─ 確定申告からは逃げられない`
- タイトル画面は `<h1>` に名前だけを置き、作品名の後半を 2 段目（`.sub2`）に下げる
  （名前を最も大きく、最初に読ませる）
- 操作説明の「怪人は常には居ない」→「カクシン様は常には居ない」（2 度目の提示）
- 期限後申告 END の「怪人は、静かに頭を下げた」→「カクシン様は、静かに頭を下げた」
  （怪異が言葉を発する唯一の場面。ここで名乗る）

**根拠の区分:** 名前をタイトルに置くこと自体は要求（ユーザー指示 2026-08-19）。
`<h1>` を名指しで要求するのは設計判断 — オーバーレイのどこかにあるだけでは、
操作説明（`.ctrl`, 0.78rem の灰色文字）に埋もれて読み飛ばされうる。
実際、当初 `<h1>` を要求しないテストを書いたところ「h1 から名前を消す」変異が生き残った。

### L-24: 非日本語ロケールのブランドトークンはラテン文字 `KAKUSHIN` で固定する

怪異の名前は全市場で 1 トークンに統一する（ユーザー決定 2026-08-19：「相手はカクシンでいい」）。
ただし**表記をロケールごとに翻字すると、統一が崩れるロケールがある。**

| ロケール | 翻字案 | 音 | 判定 |
|---|---|---|---|
| `ja` | カクシン | kakushin | 原語 |
| `ru` | Какусин | kakusin | 音が繋がる。可 |
| `es` / `en` | Kakushin | kakushin | 可 |
| `zh-Hans` | ~~确信~~ | **quèxìn** | **不可**。漢字の中国語音であり kakushin と別物。ブランドが繋がらない |

`确信` は意味（確信／確申）を渡せる代わりに、音でのブランド同一性を失う。
ユーザーが選んだのはブランド統一なので、**音を優先する**。

**決定:** 非日本語ロケールのタイトル・ストア名・実績名はラテン文字 `KAKUSHIN` で固定。
中国語本文の初出のみ `KAKUSHIN（确信）` と添えて漢字の意味も渡し、以降は `KAKUSHIN`。
`src/anoms.js` の `zh-Hans` にあった `确信大人` / `确信株式会社` はこの決定に反するため差し替える。

### 補足: `確申` という実在の略語

`確申（かくしん）`は税理士実務で使われる「確定申告」の略語である。タイトルで
`カクシン` と `確定申告` が並ぶことで、**カクシン様＝確申様＝確定申告そのものの化身**という
読みが成立する。これが元の命名意図だったかはリポジトリ内に記録が無く不明だが、
タイトルに入れると結果としてそう読めるようになる。図鑑で明示するかは未決。
